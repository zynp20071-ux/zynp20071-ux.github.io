JavaScript ile oyun döngüsü kurmakBuilding a game loop in JavaScript

Bu sitede gezen Piksel Zeynep de, 404 sayfasındaki koşu oyunu da aynı fikre dayanıyor: oyun döngüsü. Bir oyun, saniyede onlarca kez aynı üç adımı tekrarlar: girdileri oku, durumu güncelle, ekrana çiz.

Neden setInterval değil?

setInterval ekranın yenilenmesinden habersizdir; kareler bazen geç, bazen erken çizilir ve hareket titrer. Sekme arka plandayken de boşuna çalışmaya devam eder. requestAnimationFrame ise tarayıcının bir sonraki kareyi çizmeden hemen önce fonksiyonumuzu çağırır ve sekme gizlenince kendiliğinden durur.

let last = performance.now();

function loop(now) {
  // 60 FPS'e göre geçen kare sayısı (sekme geri gelince büyük sıçrama olmasın)
  const dt = Math.min(3, (now - last) / 16.67);
  last = now;

  update(dt);   // durumu güncelle
  draw();       // ekrana çiz
  requestAnimationFrame(loop);
}
requestAnimationFrame(loop);

Delta time: herkes aynı hızda koşsun

60 Hz bir ekranda döngü saniyede 60 kez, 144 Hz bir ekranda 144 kez çalışır. Hızı "kare başına 5 piksel" diye yazarsak oyun hızlı monitörde iki kat hızlı oynar. Çözüm, her hareketi geçen süreyle (dt) çarpmak. Böylece karakter her ekranda aynı hızla koşar.

Basit fizik: zıplama

Zıplama aslında iki satır: hıza her karede yerçekimi eklenir, konuma da hız.

player.vy -= 0.8 * dt;          // yerçekimi
player.y  += player.vy * dt;    // hareket

if (player.y <= 0) {            // yere indi
  player.y = 0;
  player.vy = 0;
}

Piksel Zeynep'in çok yüksekten düşünce yere çakılması da burada: yere değdiği andaki hız belli bir eşiği geçerse karakter crash durumuna geçiyor.

Durum makinesi

Karakterin yaptığı her şey bir durum: idle, walk, air, crash… Her karede yalnızca o anki durumun kodu çalışır ve bir koşul gerçekleşince durum değişir. Bu yapı sayesinde yeni bir davranış eklemek, mevcutları bozmadan yeni bir durum yazmak kadar kolay oluyor.

İpucu: Döngünün içinde her karede getBoundingClientRect() gibi sayfa yerleşimini okuyan fonksiyonlar çağırma; site kasar. Değeri bir kez ölçüp sakla, yalnızca kaydırma ya da pencere boyutu değişince güncelle.

Döngü bir kez kurulduktan sonra geri kalan her şey (animasyon, çarpışma, puan) bu üç adımın içine yerleşiyor.

Pixel Zeynep wandering around this site and the runner game on the 404 page are built on the same idea: the game loop. A game repeats the same three steps dozens of times per second: read input, update the state, draw to the screen.

Why not setInterval?

setInterval knows nothing about screen refreshes, so frames are drawn a little early or late and motion stutters. It also keeps running in background tabs. requestAnimationFrame calls our function right before the browser draws the next frame and pauses automatically when the tab is hidden.

let last = performance.now();

function loop(now) {
  // frames elapsed relative to 60 FPS (no big jump when the tab comes back)
  const dt = Math.min(3, (now - last) / 16.67);
  last = now;

  update(dt);   // update the state
  draw();       // draw to the screen
  requestAnimationFrame(loop);
}
requestAnimationFrame(loop);

Delta time: everyone runs at the same speed

On a 60 Hz screen the loop runs 60 times a second, on a 144 Hz screen 144 times. If speed is written as "5 pixels per frame", the game runs twice as fast on a fast monitor. The fix is to multiply every movement by the elapsed time (dt), so the character runs at the same speed everywhere.

Simple physics: jumping

A jump is really two lines: gravity is added to the velocity every frame, and velocity to the position.

player.vy -= 0.8 * dt;          // gravity
player.y  += player.vy * dt;    // movement

if (player.y <= 0) {            // landed
  player.y = 0;
  player.vy = 0;
}

This is also where Pixel Zeynep crashes after falling from too high: if the speed at the moment of landing passes a threshold, the character switches to the crash state.

State machine

Everything the character does is a state: idle, walk, air, crash… Each frame only the current state's code runs, and the state changes when a condition is met. Adding a new behaviour is as easy as writing a new state, without breaking the others.

Tip: Don't call layout-reading functions like getBoundingClientRect() inside the loop every frame; the page will stutter. Measure once, store the value and update it only when the page scrolls or the window is resized.

Once the loop is in place, everything else (animation, collisions, score) fits inside those three steps.
